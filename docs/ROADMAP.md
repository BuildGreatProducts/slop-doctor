## Build Philosophy

1. **Each phase ships something usable.** No phase leaves the app broken. After any phase, you can demo what you've built.
2. **Infrastructure before features.** The first phase sets up everything so feature work in later phases is fast and clean.
3. **Magic moment first.** The core value proposition works as early as possible. Everything else builds on top.
4. **Test as you go.** Don't save testing for the end. Each task includes verification.
5. **Progressive enhancement.** Start with the simplest working version, then layer on polish.
6. **Build straight through.** Work through all phases in one go; there's no need to open a pull request or stop for review between phases. For a quality pass, run your coding agent's built-in review (`/review` in Claude Code, or the built-in review in Cursor or Codex).
7. **The pipeline is proven before the show.** Phase 1 ends with a real examination completing from the CLI (`npx convex run dev:startScanForDev`), so the scanner UI in Phase 2 is built against real data, not mocks.
8. **Jev decides, code counts.** Anything that needs counting, maths or colour values stays in code; Jev only answers the questions in `docs/SLOP-TAXONOMY.md`.

Tasks marked **USER** need the founder to create an account, an OAuth app or an API key. The agent prepares everything around them and asks for the value when it gets there.

## Agent Session Guide

### How to Use This Roadmap with Your Coding Agent

1. **Start a session:** Give your coding agent the "Starting a new phase" prompt from the Prompt Templates below.
2. **Read selectively:** Each phase lists its Reference sections: the specific parts of the PRD, taxonomy, design and copy docs needed for that phase. The agent should read only those sections, not the entire documents.
3. **Let it work:** The agent reads the roadmap, finds the first unchecked task, implements it, and marks it complete.
4. **One session = one phase (ideally):** Try to complete a full phase in one session for best continuity. If you need to stop, the agent can resume from the last unchecked task.
5. **Build straight through:** Move from one phase to the next without opening a pull request in between. For a quality pass (after the core MVP phases or before launch), run your coding agent's built-in review (`/review` in Claude Code, or the built-in review in Cursor or Codex).
6. **Need more context?** If a task references a section not in the phase's Reference sections, the agent should read just that section on demand.
7. **USER tasks:** When the agent reaches a USER task, it stops, tells you exactly what to create and which command sets it, and continues once you've done it.

### Session Tips

- **Don't read everything:** The PRD and taxonomy are large. Each phase's Reference sections tell the agent exactly what to read.
- **Don't skip tasks:** Tasks are ordered intentionally. Skipping creates dependency issues.
- **Verify after each phase:** Run the app after completing a phase to confirm everything works before moving on.
- **Review with built-in tools:** When you want extra scrutiny, run `/review` (Claude Code) or the equivalent in Cursor or Codex.
- **Update the status line:** After completing tasks, update the header status: `**Status:** X/Y tasks complete` and `**Current Phase:** Phase N`.
- **Taxonomy changes go doc-first:** Edit `docs/SLOP-TAXONOMY.md`, then `convex/lib/taxonomy.ts`.
- **Fixture replay:** `pnpm seed:fixture` seeds a completed examination of `scripts/fixtures/sloppy.html` (a deliberately sloppy page) without provider keys; `pnpm seed:fixture --live` replays it over ~15 s so the waiting room and scanner can be watched. It prints the scan id; open `/chart/{id}` or `/?chart={id}`. Playwright needs a Chromium: set `PLAYWRIGHT_BROWSERS_PATH` or run `npx playwright install chromium`.
